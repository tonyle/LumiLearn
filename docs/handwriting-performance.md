# Handwriting input and saving

The worksheet uses one small canvas per question. Stored point coordinates remain normalized to the whole question cell, so existing work, server snapshots, grading and print output keep the same coordinate system.

`lib/ink-surface.ts` owns native, non-passive pointer listeners. It paints the initial contact immediately, batches subsequent segments into an animation frame, flushes the final segment on pen-up, and releases its active pointer before notifying the page. Window up/cancel handlers and a new down recover a missing end event. Touch gestures and the context menu are suppressed only in drawing mode; Move mode permits native scrolling. The newest touch gesture can replace stale touch input, which matters for capacitive styluses that have changing touch IDs. A true pen takes priority over touch; contact-size heuristics only reject broad secondary touches. These heuristics cannot provide hardware palm rejection for a stylus reported as an ordinary finger.

`PaperPage` writes completed strokes synchronously into `latest.current`, with immutable answer and stroke arrays. It does **not** update React state for each pen lift. The UI catches up after 250 ms without writing; autosave then waits 1,800 ms and checks that input is inactive. Undo, navigation and Submit read the authoritative draft, including ink not yet reflected in the UI. `readDraft` also prevents a delayed React render from reconciling a canvas against an older snapshot. Keep this contract when changing the input callbacks.

`lib/paper-save-client.ts` sends snapshots to `public/paper-save-worker.js`, where JSON serialization and authenticated PUT requests run away from the input thread. Unsupported workers use the normal fetch path. Saves are serialized by the page's revision queue. A save completion never replaces newer local ink, and failed requests never mark it saved. Existing before-unload protection compares authoritative and last-saved immutable snapshots.

Regression coverage includes 100 consecutive pen strokes, 100 consecutive touch-stylus strokes with changing IDs, missing up events, coalesced/HTTP fallback, gesture suppression, point limits, per-frame batching, no worksheet rerenders across rapid letters, and saving/navigating while the UI snapshot is delayed. Worker tests check request data, credentials, revisions and conflict handling. Desktop browser QA additionally checked rapid native strokes, Undo/Redo, switching questions and database persistence. Physical iPad stylus latency still requires device verification.
